Executive Summary & Problem Statement

The FSOC Challenge

Free Space Optical Communication (FSOC) requires precise milliradian/microradian optical beam alignment between moving transceivers (e.g., ground-to-UAV or satellite links).

  • Hardware testbeds are extremely expensive, fragile, and rigid.
  • Debugging tracking loss under atmospheric turbulence and vibration is difficult in hardware.
  • Need for rapid algorithm prototyping and repeatable performance verification.

The Software Solution

A standalone, modular Python simulator that replaces physical hardware with accurate physics and vision models:

  • Simulates moving optical beacons in virtual 3D space with Gaussian Point Spread Function (PSF).
  • Injects real-world disturbances: turbulence scintillation, cloud occlusion, motion blur, and vibration.
  • Closed-loop tracking via OpenCV contour detection, Kalman filters, and PID gimbal control.
  • Complete PySide6 mission-control GUI cockpit and automated telemetry logging.

Unique Selling Proposition (USP)

1. End-to-End Closed Loop

Unlike disjointed vision or control scripts, our pipeline runs at a continuous 30 Hz closed loop: Camera → Disturbance → CV Detection → Kalman Filter → PID Controller → Gimbal Actuation.

2. Dual Benchmark Capability

Seamlessly switches between procedural virtual scenes and judge-supplied external MP4 video feeds (Benchmark-2 support) with headless automated metrics calculation.

3. Graceful AI & Heuristic Fallback

Includes an ONNX-ready CNN candidate classifier (`ai_filter.py`) that automatically falls back to a deterministic brightness/contrast heuristic when trained weights are absent.

Technology Stack & Module Ownership

Core Technologies

  • Language: Python 3.12+ (Strict typing, immutable contracts)
  • Vision & Math: OpenCV 5.x, NumPy 2.x, SciPy, FilterPy (Kalman)
  • UI Framework: PySide6 (Qt for Python), Custom QSS, QPainter HUD
  • Packaging: PyInstaller standalone executable spec
  • Testing: Pytest (115 comprehensive unit & integration tests)

Module Architecture

  • core/contracts.py: Immutable dataclass source of truth
  • sim/: Virtual scene kinematics & Gaussian PSF render
  • disturbance/: 5-stage physical degradation pipeline
  • tracking/: Detection, Kalman filter & 5-state machine
  • control/: PID1D, anti-windup, derivative filtering & gating
  • ui/: Mission-control cockpit & real-time telemetry HUD

End-to-End System Workflow

01
Frame Generation: Virtual Scene Renderer (`sim/`) or Benchmark-2 Video Input Adapter (`core/camera/input_adapter.py`) generates a `SimFrame`.
02
Disturbance Injection: 5-stage physical pipeline (`disturbance/`) adds turbulence scintillation, cloud occlusion, motion blur, vibration, and sensor noise.
03
Tracking & State Machine: Blob detector + Kalman filter + 5-state machine (`SEARCH` ⇄ `ACQUIRE` ⇄ `TRACK` ⇄ `LOST` ⇄ `REACQUIRE`) processes the frame into a `TrackResult`.
04
Closed-Loop Control: PID controller computes pan/tilt gimbal corrections with anti-windup clamping and slew-rate limiting, feeding back to camera state.
05
Telemetry & Logging: Aggregates metrics (`TelemetryPacket`) to update UI cockpit HUD, rolling charts, and exports JSON performance logs.

Benchmark-2 & Automated Evaluation

Real Video Ingestion

The VideoInputAdapter allows any external .mp4 video file to act as the live camera feed, bypassing the synthetic generator for real-world testing against judge datasets.

Run headless evaluation instantly:

python evaluate_video.py test_beacon.mp4

Graded Metrics Computed

  • Acquisition Time: Exact duration from `SEARCH` to initial confirmed `TRACK`.
  • Lock Retention Rate: Percentage of frames maintaining valid track lock.
  • Tracking Error: Mean & Root Mean Square (RMSE) error in pixels.
  • Performance Log: Standardized JSON export (`performance_log.json`).

Verification & Rigorous Testing
